applied in package order (`branding/boot` plain diffs, then `duress-unlock-dummy`,

- Old base (`2026071500` revisions): 9/9 projects apply clean. `packages/apps/Settings`
  tree `3bb5dc8f7e35` and `packages/apps/Multiuser` tree `c86730033a91` match the
  hashes recorded in the decoy `SOURCE.md`. `frameworks/base` cannot be compared to the
  `SOURCE.md` tree hash (that one is a partial state), so it was compared to the

  For all 76 touched files the net added/removed lines are identical on old and new
  base, so no hunk changed content.
- Semantic check of the 8 files upstream also changed: upstream added a
  `devicePolicyUserRestrictions` parameter to `UserManagerService.createUserInternalUnchecked`
  and `...NoTracing`, renamed `ActivityManagerInternal.onGosPackageStateChanged`, and
  rewrote `StorageManagerService.getManageSpaceActivityIntent`. None of our patches
  reference these, and our hunks lie in other regions. This is a source read, not a

  the device carries the old type name in `/data`; flashing the new build without
  wiping data is unverified and may leave that user unrecognised.
